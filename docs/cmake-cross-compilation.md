# 🛠️ CMake Cross-Compilation Guide

CMake is a powerful and widely used build system generator. It’s commonly used for cross-compiling software for embedded Linux targets, especially when you want a modular and clean build system.

This guide walks through using CMake for cross-compilation with an embedded Linux toolchain.

---

## 📁 Project Structure Example

A typical embedded CMake project might look like this:

```plaintext
dev/examples/
├── CMakeLists.txt
├── gpio/
│ ├── main.c
│ └── CMakeLists.txt
├── uart/
│ ├── main.c
│ └── CMakeLists.txt
```

Each example is its own module, built under a top-level CMake project.

---

## 📄 Creating a Toolchain File

CMake needs a **toolchain file** to understand your cross-compilation environment.

Create a file like `arm-toolchain.cmake`:

```cmake
# arm-toolchain.cmake

set(CMAKE_SYSTEM_NAME Linux)
set(CMAKE_SYSTEM_PROCESSOR arm)

# Point to your toolchain binaries
set(CMAKE_C_COMPILER arm-linux-gnueabihf-gcc)
set(CMAKE_CXX_COMPILER arm-linux-gnueabihf-g++)

# Optional: define sysroot
set(CMAKE_SYSROOT /path/to/sysroot)
set(CMAKE_FIND_ROOT_PATH /path/to/sysroot)

# Tell CMake how to find files
set(CMAKE_FIND_ROOT_PATH_MODE_PROGRAM NEVER)
set(CMAKE_FIND_ROOT_PATH_MODE_LIBRARY ONLY)
set(CMAKE_FIND_ROOT_PATH_MODE_INCLUDE ONLY)
```
---

## 🧪 Building with CMake
Once your toolchain file is ready:

```bash
mkdir -p build
cd build
cmake .. -DCMAKE_TOOLCHAIN_FILE=../arm-toolchain.cmake
make
```
---

## 🔍 Useful CMake Flags

| Flag                     | Description                                   |
| ------------------------ | --------------------------------------------- |
| `CMAKE_SYSROOT`          | Points to the sysroot of your embedded system |
| `CMAKE_SYSTEM_NAME`      | Set to `Linux` for embedded Linux targets     |
| `CMAKE_SYSTEM_PROCESSOR` | Architecture like `arm`, `aarch64`, `riscv64` |
| `CMAKE_FIND_ROOT_PATH`   | Where to look for libraries/headers           |
| `CMAKE_C_COMPILER`       | Path to cross C compiler                      |

## 🧩 Integrating with External Libraries
If your code uses external libraries:

Ensure they are available in the sysroot

Use pkg-config with proper environment:

```bash
export PKG_CONFIG_SYSROOT_DIR=/path/to/sysroot
export PKG_CONFIG_PATH=/path/to/sysroot/usr/lib/pkgconfig
```
Then run CMake again.

## 📦 Tips for SDKs (e.g. from Yocto or Buildroot)
If you're using an SDK generated by Yocto or Buildroot:

```bash
source /opt/poky/2.5.1/environment-setup-armv7at2hf-neon-poky-linux-gnueabi
```
This sets environment variables like:

CC, CXX

PKG_CONFIG_PATH

CFLAGS, LDFLAGS

SYSROOT

CMake will auto-detect these in most cases.

##  ✅ Summary
Use CMake with a custom toolchain file to cross-compile.

Define the correct paths to compilers and sysroot.

Use environment variables to configure external dependencies.

Works seamlessly with Yocto and Buildroot SDKs.
